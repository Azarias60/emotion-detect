## 共同约束

界面重写以规范组件、统一主题、清楚的业务边界及真实业务行为为目标。已确认功能是当前范围，但并非每项功能都值得同等维护成本；若某项要求妨碍职责或生命周期自然衔接，应给出具体证据、代价及可调整的行为，由用户权衡，不为保留旧功能制造错误依赖，也不擅自删去已确认功能。原 AI 编写的参数、文案和结构不作为产品需求。

取舍优先级为：**业务需求 > 代码架构清晰 > 边界安全**。防御性设计须对应真实约束；账号归属与数据正确性仍是已确认业务要求。布局和交互方式属于明确的产品选择，须实际验收；不能从一个预设界面效果倒推出重复状态或跨模块协调流程。

先登录、保留查询按钮、推荐经确认再导航、重新选择配置时清除临时音色等，是已确认的产品选择。数据同源更新、删除后集合变化、资源缺失后的可用性及封存后可再次采集，是在这些选择和职责下产生的结果；两类内容不能混为额外功能，也不能借“自然产生”删去必要业务规则。

| 技术 | 职责 |
| --- | --- |
| React | 消费后端提供的事实与变化，派生界面及操作可用性，维护表单草稿与弹窗等局部交互状态 |
| Ant Design | 基础控件、表单、表格、弹窗、内容编排、反馈和统一主题 |
| Ant Design X | 首页与数字人页的消息列表、文字输入和快捷提问等对话控件 |
| `simple-liquid-glass` / `LiquidGlassScene` | 全站唯一玻璃渲染通路，库拥有背景捕获及渲染生命周期 |
| 现有媒体与 Markdown 能力 | 实时视频播放、暖暖素材播放，以及报告正文渲染 |
| 后端及应用业务能力 | 设备来源、语音处理、会话、检测、报告、制作任务、资源与身份等各自状态和副作用 |

字体、颜色、尺寸、圆角优先使用统一主题规范，不为每个控件自造参数。玻璃不承担业务状态或控件交互；Vue 只提供信息组织参考，不引入第二套运行时。

组件表确定呈现方式，不反向定义业务状态：加载、空内容、进度及错误只展示相应能力实际提供的事实或界面操作反馈，不为使用 `Spin`、`Alert` 等控件再造一套状态。

只做电脑端一种布局：浏览器内容区基线 **1280 × 800 CSS px**，更大窗口沿同一布局自然伸展。窄屏、移动布局暂不设计；分区比例、滚动及弹窗尺寸通过桌面基线的实际渲染与验收确定。

参考分工：检测中心内部信息组织、报告管理参考历史 Vue；首页和数字人页参考 `feat/digital-human-merge`，已核对版本固定为 [`c403249f6cf6a0a52e596174fb43d81b75c3995a`](https://github.com/qwer12345qwer12345/physiosense/tree/c403249f6cf6a0a52e596174fb43d81b75c3995a)。

## 身份、数据与生命周期

### 响应式职责

各能力拥有自己的事实与生命周期，并向使用者提供当前事实及后续变化。依赖关系贯穿后端能力、传输接入与 React，界面随收到的事实派生呈现。命令只执行所属操作，变化从事实所有者传递，不由命令逐处刷新或同步消费者。明确的导航意图由路由处理；登录后工作区的呈现由身份依赖决定。

集合、配置与任务结果是各自的事实来源；匹配列表、当前配置、可用会话及操作可用性从依赖派生。真实的不同意图可以有独立状态，例如筛选草稿与已应用条件、配置默认音色与会话临时音色。

传输接入拥有订阅、发送与连接释放；业务能力拥有事实及变化。React 通过数据接入消费这些变化，使用自己的响应式机制组织呈现。前端额外的检测控制器、报告观察服务或状态机不是目标要求，具体函数与文件组织由实现决定。划分以完整职责及使用期为依据，不因界面分栏或当前代码位置决定所有权。

### 业务职责与依赖

下表按实际业务意图划分责任，不要求每行新建服务、接口或目录。页面章节只定义相应的产品选择与呈现。

| 业务意图 | 事实、资源与责任归属 |
| --- | --- |
| 使用现场设备 | 设备与采集能力拥有连接、持续音视频来源、本轮媒体记录、输入有效性及稳定性，提供预览和采集契约 |
| 听取与识别语音 | 语音能力消费设备音频，提供转写及既有聆听、识别状态；问答能力拥有题目、回答判定和推进规则 |
| 执行一次检测 | 后端检测调度从建立报告开始，安排准备、60 秒采集、问答、封存及后续处理；问答、指标计算与模型处理分别承担自身规则和计算，产出交给所属报告 |
| 记录与查看检测事实 | 报告能力拥有本轮唯一业务数据、处理事实、账号归属及内部持久化，并提供当前事实与变化；检测中心和报告管理均为消费者 |
| 接收业务事实变化 | 传输接入连接事实所有者与使用者，管理自身订阅和连接；不承担业务执行或记录，观察结束不结束被观察的业务 |
| 进入账号工作区 | 认证能力维护可信身份，后端验证对象归属；应用入口依身份装配工作区，路由处理明确的导航意图 |
| 获得首页导览 | 导览能力拥有临时对话、推荐、资料卡和回复；消费设备语音及账号模型配置，播放能力提供实际播放状态 |
| 与数字人交流 | 陪伴能力拥有配置选择标识、临时音色选择、对话上下文和回复；当前配置与有效资源从账号对象集合派生，音视频使用期与上下文使用期分别管理 |
| 管理配置与资源 | 配置、形象、音色、原始素材各自维护账号内对象、CRUD 及引用查询；配置引用对象，不拥有被引用对象的删除权 |
| 制作形象或克隆音色 | 已提交任务拥有执行、进度、取消和产物，将产物写入对应资源集合；制作、选择、建立配置和绑定分别表达不同意图 |
| 现场录音 | 录音能力消费设备音频，拥有未提交录音与录音状态；陪伴依据该状态处理自己的聆听及播报 |
| 修改模型 Key | 账号模型配置能力拥有 Key；导览与陪伴在下一轮读取，设置弹窗只提交配置修改 |
| 编辑与查看界面 | React 组合上述能力，拥有输入草稿、筛选草稿与已应用条件、弹窗及详情选中项；Ant Design、Ant Design X 与媒体组件呈现相应内容 |

### 报告作为检测数据真相

报告能力中的报告是同一轮检测业务数据的唯一事实来源，从启动本轮时建立，始终归发起账号。同一个报告标识贯穿采集、问答、指标识别和模型分析，各过程将所属进度、结果及失败信息提供给报告能力，按需完善同一份报告。

```text
采集 / 问答 / 指标识别 / 模型分析
                ↓ 提供各自产出的数据
          报告能力中的同一份报告
                ↓ 当前事实与后续变化
              传输接入
                ↓ 更新 React 使用的报告数据
          检测中心 / 报告管理页面
```

报告能力维护报告事实、持久化和访问归属；识别能力拥有执行过程及其资源。报告管理页面是消费者，不拥有识别编排。检测中心的阶段、题目、转写、指标、正文与错误均从报告读取，不再订阅编排内部业务快照，也不另建一份“检测记录”在最后复制成报告。

报告的可观察变化是报告能力的对外契约。观察开始时取得当前账号范围内的事实，随后接收创建、修改与删除带来的变化；传输接入负责将这些变化送到 React。停止观察只结束该次订阅与连接，不改变报告、采集或后台处理的使用期。报告是否存在也由报告能力提供，依赖该报告的处理据此管理自己的使用期。

前端只展示报告能力提供的内容，随可观察变化更新，不自行判定报告是否最新、过期或尚未保存。请求成功与否、连接是否存在，都不能代替报告中的业务事实。内部写入可靠性归报告能力负责，不对页面另设保存状态、补存或写入重试流程；分析失败则是可记录的业务处理结果，界面依据报告中的该事实呈现并表达重试分析意图。此处规定职责，不预设具体事务、缓存或消息传输实现。

设备预览仍消费实时设备来源。原始媒体缓冲、计算工作队列等内部资源按用途管理，不因统一报告读入口就全部永久写入报告。后台识别与分析由后端推进，不能依赖页面继续串接请求；报告存储本身不替代执行能力。

报告内容按业务含义组织，不按采集、准备、模型结果分成数据层级。以下现有内容全部保留，具体字段及适用模式仍按真实业务契约落实：

| 内容 | 保留范围 |
| --- | --- |
| 舌象 | 质量、颜色、舌苔、裂纹、齿痕及体质相关结果 |
| 问答与转写 | 当前题目、临时转写、完整逐题问答；后端已有的独立整段语音转写按原语义保留 |
| 心率与呼吸 | 心率、呼吸频率 |
| 心率变异性 | SDNN、RMSSD、pNN50、NN50 |
| 行为 | 眨眼次数与频率、哈欠、点头、PERCLOS、说话占比等现有指标 |
| 疲劳 | 分数与程度 |
| 情绪 | 表情统计、情绪词统计 |
| 解读 | 疲劳相关建议、健康或情绪综合解读，各自保留独立业务含义 |

每项事实只维护一个权威值。现有 `advice.text` 与 `report.text` 含义不同，可同时存在；`rawReport` 又复制其中一份正文的存储路径应收敛。疲劳页直接展示已有建议，健康、情绪页展示综合解读，展示选择不产生另一份正文。截断预览、格式化时间与百分比等由原值派生；报告身份、账号归属和类型继续保留，具体字段名不在此冻结。

报告对外只需要创建时间，列表显示、日期筛选和最近报告选择统一使用它。后续补齐数据不改变创建时间，不额外引入更新时间或模型完成时间作为报告业务字段。识别内部的采集计时仍归执行能力，不因此增加报告时间项。

报告类型固定为健康、疲劳、情绪三种，沿用对应的 `health`、`fatigue`、`emotion` 模式标识。舌象是健康报告内容，临时综合分析不形成报告，数字人对话属于陪伴会话，不另立这三类报告类型。

标题由类型派生，摘要由已有内容截取；均由显示端处理，暂无内容就保持缺失，不作为报告独立维护的业务事实。综合分析直接消费报告实际内容，不依赖展示摘要。

前端从报告能力观察、查询报告并表达删除意图；启动、提前结束、取消检测和重试分析由识别能力接收。报告的建立与业务内容更新由识别过程通过报告能力完成，前端不提交指标、拼装结果或保存最终副本。命令不负责串接其他页面的刷新、分页调整或当前报告回退。

### 界面消费面

以下固定使用者需要的事实与意图，不要求新建同名服务。具体函数签名、接口路径、订阅协议及前后端类型映射属于实现选择。

| 消费场景 | 读取的事实 | 表达的意图与所属能力 |
| --- | --- | --- |
| 设备预览 | 设备提供的可用性及 WebRTC 视频来源 | 声明预览的使用条件；连接、恢复和释放归预览能力 |
| 检测中心 | 当前账号、当前模式下按创建顺序选择的报告，含准备、题目、转写、指标、处理进度及解读 | 表达账号、页面与模式的使用条件；识别能力接收启动、提前结束、取消、重试分析；题目已显示反馈交问答能力。操作已有轮次时以该报告为目标 |
| 报告管理及详情 | 同一报告集合、所选报告、逐题记录；匹配集合由已应用条件派生 | 报告能力接收删除；查询按钮只应用界面筛选条件，分页归 Table |
| 临时综合报告 | 打开时取得的完整匹配内容快照及其汇总结果 | 报告应用能力对该快照做纯计算，关闭结束本次查看，结果不写入报告集合 |
| 首页 | 导览对话、推荐、资料卡、语音及播放状态 | 导览接收文字、聆听和重新开始；推荐确认给出导航目标，路由执行导航 |
| 数字人陪伴 | 当前配置与有效资源、对话上下文、语音、播放及能力状态 | 陪伴接收配置与临时音色选择、文字、聆听、打断、重新开始及舞蹈操作 |
| 对象管理 | 当前账号配置、形象、音色、素材集合及实际引用者 | 各对象能力接收自己的新增、编辑、删除；默认音色绑定修改目标配置 |
| 制作与录音 | 对应任务的进度、结果与错误，以及现场录音状态 | 制作能力接收明确输入并管理已提交任务；录音能力接收开始、停止提交与取消；建立配置和绑定分别由明确操作提交 |
| 模型设置 | 当前账号 Key 是否配置及掩码 | 模型配置能力接收 Key 修改，弹窗维护输入草稿 |
| 登录与账号 | 可信身份及认证操作反馈 | 认证能力接收登录、注册和退出，入口观察身份变化 |

一次执行开始时绑定其账号、报告或任务目标，后续产出始终归该目标；页面当前模式、当前报告、选择器及表单草稿不决定迟到结果写到哪里。切换显示对象只改变观察对象。对既有对象的修改同样带明确目标，身份和对象归属仍由后端验证。

由此，新报告创建不会截走旧报告的分析结果，制作结果不会隐式绑定另一个配置，选择变化也不会替其他对象执行命令。这些是目标归属正确后的验收结果，不另设页面锁定或跨对象同步。

### 账号与设备作用域

- 当前版本统一先登录，再进入首页及其他工作页面。认证能力提供可信身份，应用入口据此呈现独立登录页或对应账号的工作区。
- 业务依赖可信的当前使用者及资源归属，不依赖登录页面、JWT 或 Cookie 的具体形式。后端验证实际入口的访问身份及资源权限，包括 HTTP、媒体握手、私有资源及接入后的会话消息连接；前端呈现不替代服务端保护。
- 数字人配置、形象、音色、原始素材及其制作结果、引用关系与管理操作按账号隔离。报告同样属于对应账号。
- 模型 Key 按账号管理；首页导览与数字人共同消费当前账号的配置，新 Key 从下一轮对话生效。
- 每个新账号提供现有内置数字人与官方音色作为初始内容。之后与自建内容按同样规则管理，可在本账号内编辑、删除；其他账号不受影响。不保留按固定内置 ID 禁删的界面特判。
- 同一台设备同一时间服务一位现场使用者，以一个当前账号使用设备。设备连接与持续数据源由设备能力统一拥有。
- 身份来源及入口装配保持可替换，业务沿用使用者与资源归属契约；本轮只实现已确认的登录使用方式。

## 设备与语音

### 当前实现、参考实现与本轮采用范围

| 链路 | 已核实实现 | 本轮采用范围 |
| --- | --- | --- |
| 当前分支的设备预览 | `api/preview.ts` 创建 `RTCPeerConnection`，仅接收视频；通过 HTTP `/capture/preview/session` 及 `/capture/preview/offer` 签发会话、交换 SDP。后端 `presentation/preview.py` 从设备来源订阅视频并发送 WebRTC 视频轨 | 保留这条 WebRTC 预览链路及原生 `video` 展示，不以 WebSocket 传输预览画面；HTTP 是握手通道，不是视频传输通道 |
| 参考分支的数字人实时舞台 | 固定参考版本 `api/digitalHuman.ts::createDigitalHumanTransport` 通过 WebRTC 接收数字人视频与音频，HTTP `/offer` 握手；另外用 WebSocket 传递会话事件及浏览器麦克风 PCM | 借鉴舞台布局及复用实时播放能力；当前分支尚未接入该数字人链路，不能描述为当前设备预览的实现 |
| 参考分支的首页导览 | 同文件 `createGuideTransport` 用 WebSocket 传会话事件、浏览器麦克风 PCM 和下行播报 PCM；暖暖画面使用素材播放，不是设备预览 | 保留导览交互及素材；本轮输入来自后端单片机音频，不能照搬浏览器取音频再经 WebSocket 上送的路径。会话事件与播报的接入契约仍待核实，不预设采用参考协议 |

设备视频预览、数字人生成画面、对话事件和语音输入各有独立用途。共享设备来源不等于使用同一种传输协议，也不要求先把单片机音频经预览传到浏览器再回送后端。

### 设备音频与问答的职责

设备预览、检测采集、导览、陪伴和音色录音使用同一单片机数据来源。设备能力拥有连接及持续数据，检测在其上建立本轮记录，预览继续运行。

设备取音频、切片和格式转换归设备及语音能力；转写、唤醒、语音起止、识别文字和处理阶段由所属后端能力提供。检测问答、导览、陪伴与录音按自身用途消费同一设备来源，界面呈现相应事实。

```text
设备视频 ──→ 预览 / 本轮采集输入
设备音频 ──→ 已有后端语音能力 ──→ 检测问答数据 ──→ 同一报告 ──→ 检测中心 / 报告管理
       │                   └──→ 导览 / 陪伴会话 ──→ 对应界面
       └──→ 录音能力 ──→ 克隆任务
```

语音处理、问答、导览与陪伴按共同职责表消费数据。克隆按用途取得录音，不为它强加转写流程。题目已显示的必要反馈由界面提供，回答判定、题目推进和转写处理仍由所属能力负责。

题目及回答推进规则归问答，60 秒采集时序归检测调度；导览、陪伴可以直接消费设备音频，不依赖启动检测。

**回答的判定、收尾与推进暂时沿用现有实现，后续再调整。** 本轮复用音频与状态来源，不改变答复有效性条件或结题策略。

### 首页与陪伴共用的交互规则

- 进入对应页面自动连接服务、接入单片机音频；自动聆听先待命，说“你好”唤醒后连续交流。
- 用户主动重新开启聆听，直接进入交流，无须再说“你好”；文字发送也可直接交互。
- 聆听开关只改变相应会话是否消费音频，保留该会话上下文，设备来源仍由设备能力管理。
- “你好”只负责唤醒，重复问候不清空已有对话；取消三分钟无交流自动重置。
- 重新开始由用户明确触发；会话保留范围仍按生命周期表区分，首页离页结束，陪伴同次登录接续。

`/asr/transcribe` 作为合作者提供的封装接口消费，本项目只对接其输入、输出和错误，不承担接口内部的识别实现或改造。

## 检测中心

### 任务与流程

- 进入页面自动观察设备；在线显示预览，离线呈现设备状态，恢复后自动恢复预览。进入页面本身不开始检测。
- 健康、情绪、疲劳分别呈现对应模式的任务与结果，同一时间仅一个模式采集设备数据。
- 本轮准备与采集的使用期依赖当前登录身份、检测页面与当前模式；前端表达这些使用条件，由后端依据自己的实际采集状态处理。尚未封存时中途切换模式、切离检测页或退出登录，按下表“取消”规则结束本轮与问答；模式选择、路由与退出操作不分别判断阶段并编排清理。
- 采集完成并封存后，同一份报告保留，模型处理继续，切换模式、离页或退出登录不取消；报告及结果归发起账号。页面返回时从报告观察进度与结果，不重新采集或重复调用模型。检测页内切换模式不另开设备连接，预览沿同一来源持续。
- 封存采集输入是稳定分析来源；准备结果、问答、指标与 AI 正文在产生后写入同一份报告。AI 正文等待或失败时，报告已有的指标和问答继续可见。

采集使用期与封存后的分析使用期不同。能否开始下一轮取决于采集能力可用性，旧报告是否分析完不构成页面门槛；各轮处理只依赖各自输入与报告。这一关系自然允许前一轮分析期间开始下一轮，不另设“连续检测”功能、跨轮同步或指定排队实现。

| 模式 | 用户启动后的流程 |
| --- | --- |
| 健康 | 触发舌象截图与分析；准备就绪后自动进入采集和问答，不要求第二次点击开始 |
| 情绪 | 启动后准备题目，就绪后自动采集和问答，无舌象准备 |
| 疲劳 | 启动后直接采集，无舌象准备或问答 |

用户启动时先建立所属报告，再由后端准备对应模式的输入并自动推进采集与问答。前端只提交模式，不串接舌象、题目准备及开始采集的请求。报告未建立成功时不启动本轮，呈现启动操作失败并允许重试，不形成一份待补存的独立检测结果。

问答与采集同时进行，完整采集窗口为 **60 秒**。题目显示后自动记录、转写与推进，回答处理沿用现有规则。问答提前结束仍采集到 60 秒；到时结束采集，待当前回答收尾后分析。

采集模块负责连接稳定性、必要的内部恢复与输入有效性，通过自身契约提供可用性及采集结果。检测与界面不实现断流后的同轮接续、暂停补时或问答续接。浏览器 WebRTC 预览连接中断不决定检测使用期；后端仍正常接收数据时检测继续，预览能力负责自己的连接恢复。

| 采集阶段操作 | 本轮结果 | 设备与历史记录 |
| --- | --- | --- |
| 到时或用户提前结束 | 封存已采集数据，进入模型分析 | 设备连接与预览继续，同一报告保留并继续更新，其他报告不变 |
| 取消 | 停止本轮采集与问答，清理未完成采集并移除对应未完成报告 | 设备连接与预览继续，其他报告不变 |

重试分析沿用同一报告关联的本轮输入和已有结果，不重新采集或另建报告。报告从本轮开始就在报告能力中逐步完善，不等待 AI 正文完成才复制保存第二份；内部持久化不形成页面操作流程。

检测中心按当前账号与检测模式观察最近创建的一份报告，以创建顺序选择，不因旧报告的后台更新改变观察对象。新报告建立后自然成为当前报告；取消并移除未完成报告后，自然显示该模式上一份报告，没有则呈现空状态。页面不另存一份需要同步的当前报告内容。

### 布局与组件

顶部“检测中心” `Dropdown` 提供健康、情绪、疲劳入口，替代页内模式栏。

```text
左：Metrics             中：Capture                  右：结果预览
持续展示指标            视频                         健康 / 情绪：报告 + 逐题记录
```

`Question` 从 Metrics 移至视频下方，展示当前作答；右侧记录展示本轮已完成问答。两者消费同一轮数据。报告预览展示报告提供的业务处理状态与正文开头数行，不另生成摘要或保存状态；逐题预览按题序显示问题与简短回答。点击预览查看完整详情。

| 区域 | 组件 |
| --- | --- |
| 左侧指标 | `Card`、`Descriptions` |
| 视频 | 原生 `video`，承接现有 WebRTC 设备预览 |

健康、情绪的右侧分为报告与逐题问答两个预览区；疲劳无问答，报告占满右侧。详情不截断正文或逐题原文。生理窗口展示本轮完整指标与缺测说明。弹窗开关不改变预览或任务，局部错误不掩盖其他已产生内容。

### 检测数据接入约束

职责和消费范围沿共同表落实，先核实真实数据类型与接入契约，再写测试和实现。

报告保留的业务内容见共同章节。与现有数据接入时，复用舌象与体质、`physiology`、`behavior`、`fatigue`、`expression`、`emotion_word_count`、`speech` 及缺测说明等已有领域值，不另造一套平行字段。问答记录沿用既有数据含义，保留原回答判定与推进策略。

同一报告增量写入时保留其他已有内容，删除后不由迟到结果重新创建。分析重试复用本轮输入，分析失败不抹去报告中已有结果。是否已经封存由后端真实采集事实判断，界面阶段与请求返回时机不能替代它。以上是各能力必须保证的数据和生命周期约束。

### 由这些职责产生的验收预期

下表用于检查职责是否落实，不代表还要分别开发一套同步、刷新或回退流程。观察关系和使用期依赖需要由所属能力正确实现。

| 已有职责或依赖 | 应自然呈现的结果 |
| --- | --- |
| 两页都观察同一报告 | 指标、问答与解读补齐后，两页读到同一事实，不需要互相通知或复制保存 |
| 当前报告按账号、模式及创建顺序选择 | 新建后呈现新报告；取消并移除本轮后显示上一份或空状态；旧报告更新不抢占当前选择 |
| 匹配集合从全部报告和已应用条件派生 | 报告更新或删除后，Table 与下次打开综合报告所用的集合随之变化，无须再执行一次查询 |
| Table 接收完整匹配集合并拥有分页 | 删除后的有效页由 Table 呈现，删除命令不处理页码 |
| 采集使用期依赖身份、页面与模式 | 采集中依赖失效会取消本轮；路由、模式选择和退出操作无需各自复制取消规则 |
| 分析只消费所属报告及封存输入，采集能力管理当前采集可用性 | 旧报告分析不阻止新的可用采集，新旧报告分别更新；页面不编排两轮先后 |
| 采集模块提供输入，预览独立消费同一来源 | 预览连接中断不改变仍正常取数的检测；页面不编排采集恢复或补时 |
| 封存后处理归后端且仍依赖原报告 | 离页、退出后继续补齐；报告删除后相关处理结束，已删除报告不会被迟到结果恢复 |

## 报告管理

参考历史 Vue，顶部筛选区，下方 `Table` 与内置分页，详情使用弹窗。综合分析整合进入报告管理，不保留独立页面与顶层导航。

```text
当前账号报告集合 ＋ 点击“查询”后生效的条件
                         ↓
                 匹配的报告集合（派生）
                    ↙           ↘
          Table 展示与内置分页   临时综合分析
```

报告能力拥有报告集合，报告管理页面和检测中心都是消费者。识别过程中产生的数据和 AI 正文均更新对应报告，前端不再从采集编排另取一份数据。表单草稿与已生效条件分别表达编辑和应用意图；修改草稿不改变结果，点击“查询”才应用。新增、更新、删除反映到原集合，匹配结果自然变化。Table 与综合分析消费同一份完整匹配集合，分析范围不受当前页影响。

关键词匹配报告已有的文字内容，包括逐题问答、建议和综合解读，不受显示摘要的截断范围限制；尚未产生的内容不参与匹配。报告内容补齐后，当前已生效条件下的匹配集合自然更新。类型、创建日期与关键词条件共同决定查询结果。

Table 自主管理分页和页码越界。删除后当前页为空，由 Table 据剩余数据呈现有效页面，删除命令不负责跳页。这里以完整 `dataSource` 为前提，Table 不会替后端加载尚未取得的数据；加载方案仍待契约落实。

| 内容 | 组件与约定 |
| --- | --- |
| 报告类型、关键词、日期范围筛选 | `Form`、`Select`、`Input`、`DatePicker.RangePicker`、查询 `Button` |
| 报告列表 | `Table`；列为报告类型、报告信息（标题与摘要）、创建时间、操作 |
| 报告详情 | `Modal`、已有 Markdown 能力 |
| 逐题问答详情 | 健康、情绪提供入口，使用 `Modal`、`Timeline`；疲劳不提供 |
| 删除确认 | `Popconfirm` |
| 综合报告入口 | “综合报告” `Button` |
| 综合报告内容 | `Modal`、`Descriptions`、已有 Markdown 能力 |
| 局部加载、空数据、错误 | `Spin`、`Empty`、`Alert` |

健康、情绪的逐题问题与回答随报告持久化，刷新、重新登录后可看；检测中心与历史详情读取同一轮事实。逐题记录属于报告，随报告删除，删除命令不改变筛选或页码。数字人配置、形象、音色和原始素材是独立对象，互不级联删除。

报告存在是相关识别处理的使用条件。用户删除处理中报告后，处理能力根据依赖变化结束，不再向该报告补写或重新创建它；删除操作只负责删除报告。退出登录不删除已完成采集的报告，因此后台分析仍可继续。

“查看综合报告”表达一次临时汇总意图，范围为当次取得的已应用筛选下全部匹配报告。保留现有 `ReportingService.analyze_reports` 的内容功能：**报告数量、类型构成、近期报告已有文字摘录及原有说明**，近期摘录沿用现有范围和规则。汇总消费报告原始文字，不恢复独立维护的摘要字段；无可摘录文字时按原规则省略，该报告仍参与数量和构成统计。

已核实该函数只统计、摘录并拼接文字，没有模型调用。按上述读取关系，完整匹配内容来自报告集合，因此将这项计算收敛为前端报告应用能力中的纯函数：输入本次查看的匹配内容快照，输出汇总，弹窗负责呈现。输入来自 React 已接收的报告集合，不另建分析任务、处理进度、二次查询或保存流程；替换后移除旧的保存型汇总路径，保留一处计算实现。

综合分析暂不扩展能力，不增加模型生成的跨报告结论、趋势计算或改善判断。此前所称“综合解读”在此只指原有汇总文字。已确认的共享筛选、临时弹窗和不保存结果仍保留，替换原来的单独日期分析与保存跳转；内容功能不因此扩大。

本次计算使用打开时取得的输入，报告本身仍持续更新；弹窗期间不自动重算，也不提供“重新分析”按钮。关闭后再次打开，使用当次取得的匹配内容重新生成，不宣称前端能够证明数据为全局最新。结果仅供临时查看，没有第二套分析筛选表单或额外生成确认，不保存为历史报告、不增加列表条目，也不提供关联报告或“查看已保存报告”跳转。

## 数字人页

### 对象与派生关系

| 对象 | 内容与所有权 |
| --- | --- |
| 数字人配置 | 名称、形象引用、默认音色引用 |
| 形象 | 人物外观及属于其自身的播放资源 |
| 音色 | 可独立选择、克隆、供配置引用的声音及其自身资源 |
| 原始素材 | 源照片、录音或视频，独立于配置及产物管理 |

四类对象按账号管理，配置是引用关系，不拥有被引用对象的删除权。

陪伴从配置及资源集合读取有效内容；配置数据变化后当前会话随依赖更新，保存操作只负责修改配置。形象使用当前配置引用的形象；音色优先使用会话手动临时选择，否则使用配置默认音色。重新选择数字人配置时清除临时音色选择。配置默认绑定需要明确提交，编辑草稿和临时选择不写成永久配置。

陪伴能力在有效形象或音色变化时停止当前回复并保留上下文。当前配置缺失时不建立可用会话连接，上下文仍遵守同次登录内保留的使用期；形象或音色缺失时，对应画面或播报不可用并提示重新选择，其他对象保留，不自动替换资源。

### 三栏与主要组件

| 区域 | 内容与组件 |
| --- | --- |
| 左上选择区 | 数字人配置与当前音色两个 `Select`，管理 `Button`；主动重新读取集合的 `Button` 放在此区，不承担其他操作后的同步 |
| 左侧对话 | Ant Design X `Bubble.List`、`Sender`、`Prompts` |
| 对话操作 | 聆听开关、打断、重新开始 `Button` |
| 中间实时画面 | 原生 `video`；参考分支为 WebRTC 数字人音视频，与设备预览为不同链路，当前尚未接入 |
| 舞台状态与操作 | `Spin`、`Alert`；重试、浏览器限制时手动播放、舞蹈播放 `Button` |
| 右侧运行状态与能力说明 | 常驻 `Descriptions`，连接状态用 `Badge`，业务阶段用 `Tag`；重复信息只出现一次，简短能力说明不加折叠 |
| 右侧三个入口 | 制作数字人、音色克隆与绑定、模型 Key 设置 `Button`，各自打开独立 `Modal` |

陪伴的“重新开始”停止当前回复，清空本次对话、记忆、情绪和推荐，回到已唤醒可直接交流的状态。它只作用于会话，当前形象、音色、模型配置及后台任务保持各自状态。首页使用相同的显式重置原则，其会话生命周期仍独立。

舞蹈是当前陪伴会话的动作：对话邀请保留“播放”和“下次吧”；当前形象支持舞蹈时，中间画面区提供独立播放按钮。两个入口共用同一会话动作，制作能力负责产出资源。

### 管理与独立删除

管理 `Modal` 用 `Tabs` 分别呈现配置、形象、音色、原始素材，各页签用 `Table` 展示对应集合与操作。弹窗只做组合，各页签连接各自能力。

配置新增、编辑复用一份 `Modal` 内的 `Form`、`Input`、`Select`，编辑名称、形象与默认音色。用户可以用已有资源自由组合，不需要重新制作。音色列表与删除统一放在管理弹窗，克隆弹窗专注任务与明确提交绑定。

用户的删除意图只针对目标对象及其自身资源，独立的配置、形象、音色、原始素材互不级联删除。引用查询提供实际引用者及影响，警告 `Modal` 据此展示并接收取消或确认，删除操作不因弹窗布局而拥有其他对象。

引用者保留原引用，消费者据此呈现资源缺失。删除配置只删配置关系；删除源文件只删该源文件；物理资源边界归工程核实。删除命令不替换会话选择、不刷新各页面。

## 实施前的结构差距

以下是调查材料：当前代码及固定参考版本提供的问题证据，用于解释改造理由，不是一份追加任务清单，也不代表历史行为需要全部保留。本轮重新核实了检测编排、报告保存与列表、设备契约、入口装配和参考分支的会话及对象归属；实际落实以本文选定关系及下方实施规划为准。

| 证据 | 差距与应落实的归属 |
| --- | --- |
| 参考分支 `frontend/src/api/digitalHuman.ts`、`api/voiceClone.ts` 使用浏览器 `getUserMedia`；主后端问答已从设备记录切片，以 16kHz 单声道 PCM16 交给 `SpeechService` | 导览、陪伴、录音有真实共享来源需求（A1）；复用设备音频与已有后端语音结果，不另建浏览器采集及前端语音判断 |
| 参考分支 `app/useDigitalHuman.ts` 卸载销毁会话；引擎 `MicrophoneConnection` 在连接中持有上下文并于关闭时清理 | 传输连接及界面挂载拥有了不同使用期的业务上下文（A2、A4），应按账号会话与实际资源使用期分清 |
| 陪伴前端三分钟自动重置，引擎裸问候触发重置 | 唤醒与显式重新开始分开，两页采用共同语音规则 |

| 参考分支素材与模型配置沿引擎全局数据组织 | 未落实账号作用域；后端对象访问、引用查询、任务结果和 Key 配置均需遵守账号归属 |

| `CaptureStatus`、`DevicePreview` 定义在 `domain/detection.ts`，通用 `application/preview.ts` 导入检测域 | 设备已有跨场景使用需求（A1、A3），契约应归设备职责，消费者不为使用设备而依赖检测模块 |
| `createDetectionSession` 持有准备、问答、指标及报告快照，最后调用 `saveDetection` 新建历史报告 | 完整数据被编排持有并在保存时复制（A2）；需支持报告从本轮开始按需更新，统一检测中心与历史读入口，移除复制路径 |
| `createDetectionSession` 用可变的本轮 `token` 及快照贯穿分析，报告返回后才释放令牌；页面据 `phase` 判断占用 | 运行实例及资源须按所属轮次与实际采集使用期归属（A2、A4）；界面不把旧报告分析当作采集占用，也不为下一轮复制一套协调流程 |
| 后端 `Detection` 已按轮次持有媒体、问答、计算锁和结果缓存，`FacePhysService` 在计算入口内部串行使用驻留资源 | 保留这些已有职责作为重构基础；每轮输入与结果归原报告，资源调度留在计算能力内部，不把内部串行执行扩大为页面等待全部分析完成 |
| `useDetectionSession` 在登录工作区持有三模式会话，切换模式不取消采集，卸载时却取消所有会话 | 生命周期所有权与需求不符（A2、A4），需按实际采集使用期及封存事实管理，不能在各个路由、退出按钮中堆叠清理调用 |
| `analyze()` 在 `gateway.finish()` 返回前设置 `phase = measuring`；后端封存早于当前回答收尾 | 界面阶段不能裁决采集是否完成，需提供真实封存事实并由所属能力据此维持使用期 |
| 后端检测在带到期清理的内存表中；已有计算锁及结果缓存；当前通用 `message` 混合多种失败 | 复用已有计算与重试基础，可读结果归报告，资源和后台执行归识别；错误归对应操作或内容，不因资源清理抹去其他结果 |
| 检测路由用 `X-Detection-Token` 取记录，`Detection` 未记账号，路由未注入 `current_principal` | 沿已有认证边界落实任务账号归属及对象权限（A2），后台结果始终归发起账号 |
| 当前 `saveDetection` 将完整结果放入 `result`，又通过 `reportText` 把其中正文复制到 `rawReport` | 保留语义不同的疲劳建议与综合解读，收敛重复正文存储，每项业务事实保持一个权威位置 |

各批次围绕具体契约核实尚不确定的技术条件：现有类型及缺失语义、报告观察的传输接入、设备音频消费、引擎会话拆分、账号内物理资源边界，以及组件与媒体的实际组合。将证据带回所属模型，确定实际修改范围；不把所有可能的重试、迟到请求或故障情形另列成一套防御性工程。身份及对象归属、持久化和资源释放随所属能力一起落实。

测试范围与待调整处见上方职责映射；验收依据各页已确认的产品选择与派生预期，不把讨论术语或未采纳方案升级为要求。

派生结果的验收要沿同一依赖验证：改变所属事实或使用条件后，消费者应呈现相应结果；不通过给页面额外补刷新、回退、同步或恢复调用来使测试通过。

不复制 Table 内部分页算法做业务逻辑，不用测试数量代替行为验证。依据选定契约解释测试结果，未运行的检查不宣称通过；界面还需对照参考，在桌面基线实际渲染并进行真机调试。
