# 真人照片 → 完好的实时数字人 · 一键链路设计

> 目标：**一张真人照片 + 一段录音进去，一个带 idle1/2/3、greet、talk 全套动作段和克隆音色、
> 能在陪伴页直接对话的 LiveTalking 数字人出来**，全程一条命令、傻瓜式。
> 本文是设计文档（2026-10-19），落地工作量见文末估计。

---

## ★ 第一原则：全链路闭嘴，只迁动作

**这条链路的最终形态是 wav2lip 实时驱动口型——嘴由音频说了算，生成侧一律不碰嘴。**

1. 所有 SCAIL 动作段（idle1/2/3、greet、talk、encourage/praise/comfort）和所有 LTX 过渡：
   提示词**只描述动作、姿态、位置锁定**，不加任何"让他说话"的提示词。
   3D 卡通库时代为让 talk 段张嘴用过引号语音那套（`saying 'ba ba ba ba…'` + 音色描述），
   **本链路全段禁用**——wav2lip 会用音频逐帧重画嘴，源片段的嘴动既看不见、也没必要。
2. 每条配方都带**闭嘴锁定语**（mouth stays closed and perfectly still / lips do not move /
   he is not talking），负面词含 talking / mouth opening / lips moving。
   驱动视频（talk.mp4 等）自带的嘴部开合也要靠这段压住——v7 配方已验证有效。
3. 配方派生来源：从 `recipes/scail_3d_antijitter.json`（v7 闭嘴版）换角色描述派生真人版；
   **不要**从 `scail_3d_talk.json` 或任何引号语音版派生。
4. 自检门：**每一段**（含 talk 段和每一个过渡）都要过"嘴静"（嘴/额差异比 ≤2）。
   3D 库时代 idle2 曾经因 seed 层随机性"待机说话"（嘴/额比 11.26），这个坑在真人版
   靠配方 + 全段关门直接排除。
5. 过渡配方沿用 `recipes/ltx_transition_v28.json`——它本来就是纯动作版
   （负面词明确排除 talking / mouth opening / lips moving / smile / facial expression），无需改动。

## 0. 一句话链路

```
照片.jpg + 录音.wav + 稿子.txt
   │  tools/make_avatar.bat（一条命令，8 个阶段全自动）
   ▼
data/avatars/<名字>/            ← full_imgs（720×1280 帧序列）+ face_imgs（256 对齐脸）
   │                                + coords.pkl（逐帧人脸框）+ ranges.json（状态机段表）
data/drop/<名字>.wav + .txt     ← 克隆音色（CosyVoice3 zero-shot）
data/presets.json               ← 形象+音色配对声明
   ▼
陪伴页「数字人」芯片多一项 → 点一下，形象和声音一起换，直接对话
```

## 1. 为什么这条链路成立（复用什么）

| 需要的能力 | 已有什么 | 复用方式 |
|---|---|---|
| 照片 → 会动的片段 | SCAIL-2 图生视频，**姿态驱动**（参考图 + 驱动视频） | 驱动视频用 `E:\Comfyui\{idle1,idle2,idle3,greet,talk}.mp4`——姿态序列与参考形象无关，同一套动作库可驱动任意照片 |
| 5 个动作段的质量配方 | `digital-human/recipes/scail_3d_antijitter.json`（v7 位置锁定+闭嘴）、`scail_greet_base.json`、`scail_3d_talk.json` | 真人版只需把角色描述从 "cute stylized 3D animated character" 换成真人描述，**位置锁定语/负面词原样保留**（那些是治漂移的，与形象无关） |
| 段间过渡 | LTX-2.3 首尾帧配方 `ltx_transition_v28.json` + `graphs/ltx_flf.py` | 段与段之间熔接；也可关掉走硬切（见 §6 风险） |
| 治人物漂移 | v6 脚底锚定几何稳定化（实测漂移 38px→0.2px，纯仿射零调色） | 脚本思路在 `scratch/emotionDetect/talk_chain/run_stab_v6.py`；半身照无脚，锚点改头顶+肩线 |
| 片段 → LiveTalking 形象格式 | 引擎自带 `avatars/wav2lip/genavatar_stream.py`（人脸检测+256 对齐+coords.pkl） | 片段拼成一条视频喂进去即可，**零改动** |
| 状态机段表 | `data/avatars/yy/ranges.json` 就是现成格式（`{段名: {range:[起,止]}}`） | 按拼接时的帧偏移生成 |
| 声音克隆 | CosyVoice3 zero-shot：`data/drop/<名>.wav` + 同名 `.txt`，`list_voices()` 自动发现 | 录音裁静音后投递，引擎原生路径 |
| 形象+音色配对 | `server/assets.py` 的 PRESETS 表 + 页面「数字人」芯片 | 加一个小增强（§4），让配对可声明式注册 |
| 质量门槛/QA | `tools/metrics_check.py`、`qa_strips.py`、GLM 核查工作流 | 自检阶段直接跑 |

## 2. 八个阶段（每阶段的输入/产出/耗时）

### 阶段 1 · 素材体检（秒级）
- **照片**：分辨率 ≥ 768×1152、insightface 能检出正脸、光照均匀、背景简洁（复杂背景给警告并建议纯色墙/布）、无水印文字。
- **录音**：响度归一化、**自动裁首尾静音**（zzf2 的教训：5.01s 里前 2.1s 静音，zero-shot 会把静音当语速学走，合成被拖慢）；时长 4~12s。
- **稿子**：与录音时长做字/秒粗检（正常 3~6 字/秒），差太远提示核对。
- 不合格**立即给出可操作的重拍指引**，不带着病素材往下跑。

### 阶段 2 · 照片 → 5 个动作段（SCAIL-2，约 20~40 min）
- 参考图：用户照片按既有工艺裁成 **704×1280 竖版、人物居中**（半身取景，头顶留 ~8%）。
- 驱动视频：复用 `E:\Comfyui\` 下 5 个源（idle1/2/3、greet、talk）。
- 配方：真人版反抖动配方，从 `scail_3d_antijitter.json`（v7：位置锁定 + 静态机位 + 纯色暗背景 +
  睁眼 + **闭嘴**）换角色描述派生——遵守 ★第一原则，全段无说话提示词。
- **每段掷 5 个 seed 自动优选**（既有门槛：漂移 |dx|≤8px、睁眼、背景四角均匀、
  **嘴静（嘴/额差异比 ≤2，talk 段同样要闭闭嘴**——嘴归 wav2lip）。
- 产出：5 段 mp4，20fps，704×1280。

### 阶段 3 · 段间过渡（LTX-2.3，约 30~60 min，可关）
- 默认开：按 `ltx_transition_v28.json` 熔接（状态机实际用到的接续：idle↔idle×3、idle→greet、greet→talk、idle→talk、talk→idle×3、talk2talk）。
- 该配方是纯动作版（负面词排除 talking/mouth opening/lips moving），遵守 ★第一原则，无需加说话提示词。
- 兜底 `--no-transitions`：硬切。既有实测：端点对齐后接缝帧差 3~4，直切基线 13~21，**硬切是可接受的降级**。

### 阶段 4 · 几何稳定化（约 10 min）
- 复用 v6 脚底锚定思路：多尺度模板匹配测头部位移 + 鲁棒拟合（离群剔除+二次多项式）+ 以锚点平移缩放。
- **真人半身照锚点改「头顶 + 双肩线」**（没有脚），尺度用脸宽。
- 纯仿射、零调色。

**2026-10-21 鬼子实证的稳定化配方（`studio/stabilize_segments.py`，取代上述初版设计）**：
- **测量源用 insightface 脸盒**（OpenCV haarcascade+模板匹配会系统性低估漂移：idle1 真实脸宽 +36%，模板拟合只给 +19%；真人暗夜景匹配分仅 0.79~0.87）。**脚底锚定对真人失效**：暗背景下 `亮度>45` 抓到画面底边噪声（脚底 y 恒为 1279）。
- **顺序：全局中位数剔假框 → 插值 → 中值 k5 → 轻平均 k3 → 二轮迭代**。三个教训：①必须先剔假框再插值（漏检段被线性插值会拉出垃圾值把局部中位数拖低，假框逃过剔除，稳后极差反而 65%）；②不要对已平滑轨迹二次平滑（会把真实特征抹掉）；③k=9 平均/二次多项式都会毁掉持续 15 帧的特征或在端点外插。
- **全局统一目标**（全部段脸宽/脸位中位数）是段间接缝无缝的前提；验收线：稳后脸宽极差 <5%、端点一致性 <5%。
- **端点截断规则（关键）**：SCAIL 漂移让段尾常是大幅降采样的近景帧（idle1 尾脸宽 243 vs 目标 191 = 0.79x）。**降采样端点 LTX 无法插值**（配对尖峰恒 32~34，57/81 帧都修不好；而放大端点只是变模糊、可以插值）——**把段截到 warp≈1 的帧**（idle1 截到 f20，warp 0.98），三个出口配对尖峰 34.6/32.6/32.9 → 6.18/7.50/5.24。截断后备原段。

### 阶段 5 · 合成 LiveTalking 形象（约 5 min）
- 5 段（+过渡）按状态机顺序拼成一条 **720×1280 @ 25fps** 视频（SCAIL 出的是 20fps，用 ffmpeg
  补帧转 25——补帧不改变动作真实速度），记录每段帧偏移。
- 喂 `genavatar_stream.py`（`--avatar_id <名字> --video_path 拼接视频`）→ `full_imgs/ face_imgs/ coords.pkl`。
- 按偏移写 `data/avatars/<名字>/ranges.json`。**硬性规格**（`state_machine.load_avatar_plan` 的解析要求，
  不满足整张表会被忽略、退回默认时间线）：
  - 顶层必须是 dict 且含 `_total`（总帧数）；`_fps` 写明帧率；
  - 至少一个 `idle*` 段 + 一个 `talk` 段（缺一个整表作废）；`talk2` 可选；
  - 动作段名只能取 `greet / encourage / praise / comfort / dance`（LLM 的动作标签就这些）；
  - 名字含 `_to_` 的段是过渡（如 `idle_to_talk`、`talk_to_idle`）；
  - 每段格式 `{"range": [起, 止]}`（闭区间，和 yy 的 1408 帧表一致）。
- 落到 `data/avatars/<名字>/`。
- **P0 只做 5 段**（idle1/2/3 + greet + talk，对应 `E:\Comfyui\` 下 5 个驱动视频）；
  encourage/praise/comfort 列为 P2——那三段没有独立驱动视频，但**现有段库里这三段的帧序列
  本身就是姿态驱动素材**，截出来即可当驱动视频用（一次性准备）。

### 阶段 6 · 声音克隆（约 1 min）
- 录音裁静音 → `data/drop/<名字>.wav` + `data/drop/<名字>.txt`（逐字稿）。
- 引擎 `list_voices()` 自动发现；CosyVoice3 用当前模型重新注册（零样本，音色最准的一条路）。
- **不训练 spk2info.pt**（那要几小时素材）；ref 路径注册只要几秒。

### 阶段 7 · 配对注册（秒级）
- 写 `data/presets.json`：`[{"id":"<名字>","name":"<名字>","avatar":"<名字>","voice":"<名字>","note":"照片生成 + 录音克隆"}]`。
- 引擎侧小增强见 §4；不重启也能生效（`/api/assets` 每次实时扫）。

### 阶段 8 · 自检 + 交付（约 5 min）
- 逐项门槛：总帧数、人脸检出率 ≥99%、**每一段嘴静（嘴/额差异比 ≤2——含 talk 段和所有过渡，
  这是 ★第一原则的自检门）**、接缝帧差、背景四角均匀、漂移。
- 生成 QA 拼图（既有 `qa_strips.py`）。
- 打印一句话：*打开 http://127.0.0.1:4173/detect/companion ，「数字人」里点 `<名字>` 就能对话*。

## 3. 一键入口（目标 UX）

```bat
REM 最简：照片 + 录音 + 稿子
tools\make_avatar.bat --photo C:\Users\我\Desktop\photo.jpg ^
                     --voice C:\Users\我\Desktop\rec.wav ^
                     --text  C:\Users\我\Desktop\rec.txt ^
                     --name  xiaoming

REM 常用可选
--no-transitions     跳过 LTX 过渡（快 1 小时，硬切降级）
--seeds 8            每段多掷几个种子（质量优先）
--keep-temp          保留中间产物便于复查
```

跑完打印：每阶段耗时、各段优选 seed、自检结果表、QA 拼图路径、页面地址。
中途任何阶段不合格：**停在那一步并说清要用户做什么**（重拍照片/重录/换稿），不带着病素材往下跑。

## 4. 引擎要动的地方（都是小补丁）

1. **`server/assets.py` · `list_presets()` 合并 `data/presets.json`**（约 15 行）
   现在配对表写死在 PRESETS 里，新数字人必须改代码。改成：PRESETS 之后合并外部文件
   （按 id 去重），声明式注册，对老用户零影响。
2. **`avatars/wav2lip/genavatar_stream.py` 无需改动**（吃视频吐形象）；阶段 5 先用 ffmpeg 拼视频即可。
3. （可选）`tools/make_avatar.py` 新增，串联 §2 各阶段；SCAIL/LTX 调用走既有 `graphs/` + ComfyUI HTTP API（8188）。

## 5. 和「3D 卡通库」做法的差异（真人版专门处理）

| 环节 | 3D 卡通库当时 | 真人照片版 |
|---|---|---|
| 参考图 | 豆包截图（带水印，后来清理） | 用户照片；体检阶段查水印/文字，不干净就拦住 |
| 锚点 | 脚底（全身取景） | 头顶+肩线（半身取景，没有脚） |
| talk 段嘴型 | 引号语音提示词让嘴动 | **全链路闭嘴**（★第一原则）：wav2lip 用音频实时驱动，源片段和过渡一律不加说话提示词 |
| 过渡 | 20 个全做 | 只做状态机用到的接续；硬切兜底；沿用纯动作版 LTX 配方 |
| 音色 | 段库时代不涉及 | 录音 zero-shot 克隆（裁静音是关键） |
| 背景 | 纯黑虚空（screen 混合） | 纯色暗背景；与陪伴页全息舞台一致即可 |

## 6. 风险与对策（全部来自前几周的实战教训）

| 风险 | 概率 | 对策 |
|---|---|---|
| SCAIL 对真人参考图漂移/形变比卡通更敏感 | 高 | 稳定化兜底 + 每段 5 seed 严选；仍不达标的段自动重掷（上限 N 次） |
| 眨眼/张嘴是 seed 彩票 | 高 | 既有门槛脚本自动优选；真人脸检出比卡通稳，成功率应更高 |
| 录音静音被学成语速 | 高（已实证） | 阶段 1 强制裁静音 + 字/秒校验 |
| 照片背景复杂，生成穿帮 | 中 | 体检阶段警告；配方锁纯色暗背景；提示用纯色墙/布 |
| 半身照无脚，锚点失效 | 中（设计已知） | 锚点改头顶+肩线，尺度用脸宽 |
| LTX 过渡引入形变 | 中 | 过渡段也跑稳定化；不达标自动退回硬切 |
| insightface 检不出某些正脸 | 低 | 体检阶段先检；检不出给重拍指引 |
| 侧脸/多角度 | — | **产品边界：只做正面**，文档写明 |

## 8. 验收标准（做完怎么算成）

1. 一条命令，照片+录音进，`data/avatars/<名字>/` 与配对就位，无需手改任何代码。
2. 陪伴页「数字人」出现新芯片，点进去形象与声音都是这个人（声音是录音克隆，不是默认音色）。
3. idle1/2/3 待机循环、greet 打招呼、talk 说话（wav2lip 实时口型）全部能跑，无黑帧、无冻帧。
4. 自检表全绿；QA 拼图过 GLM 视觉核查（人物一致、无漂移、背景干净）。
5. 中途失败有明确的人工指引，不静默出错。
